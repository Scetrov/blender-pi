# Privacy (initial design)

This repository contains no project-operated telemetry client. The artist-started bridge binds and accepts only literal loopback connections. A real Blender network observation of bridge startup and handshake found only loopback sockets; it does not claim that later trusted Python or installed add-ons cannot use the network. Project transport code sends no prompts, scene data, receipts, code, or artifacts to a project-operated remote service. Pi itself and the user's chosen model provider have their **own** data handling terms; this policy does not describe or override them. The artist remains responsible for deciding what scene details to submit to a model or trusted script. Full-trust Blender Python and installed add-ons may use the network or access local files; pre-execution approvals are not enforceable per-effect mediation.

Pairing credentials stay in process memory and are cleared from bridge state on revocation, disconnect or stop; do not infer that Python memory has been securely erased. Current diagnostics store at most 16 safe error codes with random correlation IDs in Blender memory until exit; they do not write logs to disk. Inspection reports and captured images are written under the Blender user configuration `blender-pi/artifacts/session-<bridge-session-generation>/` directory (owner-only on POSIX); descriptors include an opaque ID, role, media type, canonical path, byte count, and SHA-256. They remain after bridge stop and are eligible for cleanup seven days after creation when the next artifact session is used. A private ownership index limits each session to 64 generated files and 64 MiB; cleanup checks indexed filename, inode, size, creation metadata, and digest before deletion. It scans at most 256 session directories per invocation; excess directories or unindexed/modified files need manual review and are never silently deleted. No periodic cleanup occurs while the bridge is idle. Pi-side verification checks allowed paths, sizes, and digest before returning the same bytes for later tool attachments. Checkpoints are stored separately under `blender-pi/recovery/` with their own retention policy and are never subject to evidence cleanup. Receipts are retained in bounded bridge memory, not written to disk. See [threat model](threat-model.md), [recovery](recovery.md), and [security policy](../SECURITY.md).
