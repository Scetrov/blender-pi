# Release process (planned, not active)

The offline packaging command `npm run release:build` produces `dist/release/blender_pi-<version>.zip` and `dist/release/scetrov-blender-pi-<version>.tgz` from the same local source. It verifies the checked-in bridge release metadata and file digest, requires matching npm and Blender manifest versions, writes a ZIP with sorted allowlisted members and fixed timestamps/modes, and invokes npm pack offline with lifecycle scripts disabled. Blender's archive includes GPL bridge source and its license plus MIT wire source and its notice. The npm tarball includes the bridge source, metadata, skills and Pi code, but no bundled host peers or runtime dependencies. `dist/` is ignored; build twice and compare SHA-256 before release, then validate the ZIP with Blender 5.2.2's `--command extension validate`. Building does not install or publish either artifact and needs only the existing Node.js, npm and system Python; it downloads nothing at runtime.

There are no published releases and no configured CI release workflow yet. Before publication: complete real Blender 5.2 integration on Linux x64 and Windows x64; verify packed Pi and GPL Blender artifacts include their source/license notices; run protocol, security, dependency, license and package checks; produce checksums, SBOMs and provenance from the same signed source tag; and obtain maintainer release approval in a protected environment. Use trusted npm publishing where available, not a long-lived registry token. Refer to [compatibility](compatibility.md), [licensing](licensing.md), [security](../SECURITY.md), and the [release template](../.github/RELEASE_TEMPLATE.md).

Archive the completed OpenSpec implementation change **before the final signed conventional commit and PR**. Publication approval and verification of public npm installation, pi.dev discovery, GitHub release artifacts, checksums, SBOMs and provenance belong to the **[separate release checklist](release-checklist.md)**; archiving implementation does not imply publication succeeded. First release has no prior stable version to roll back to: verify clean uninstall, revocation and checkpoint recovery; if a prior candidate is available, verify it separately before claiming a downgrade path. Do not publish while private vulnerability reporting or required hosted settings are unverified.
