# Initial support and CI matrix

The first stable release targets **Blender 5.2+ on Linux x64 and Windows x64**. This is a release target, not a claim of release qualification. The package is not yet released. `.github/workflows/validation.yml` declares unit and real-Blender headless inspection and Pi-to-Blender lifecycle jobs on both target operating systems. Hosted Linux passed the headless suite on the CI handoff branch at `9cd1a2b`; Windows static/unit validation passed but its GPU-dependent Workbench test crashed on the standard hosted VM, so Windows end-to-end and release validation remain open. Blender 5.2.2 LTS is the point release used for baseline validation; the archive and its SHA-256 manifest must be pinned in test acquisition before jobs run. Future 5.2 maintenance releases require compatibility revalidation.

| Platform | Initial release | Planned real-Blender CI | Limitations / gate |
| --- | --- | --- | --- |
| Linux x64 | Targeted | Public-repository `ubuntu-24.04` x64 runner; pinned official Linux x64 archive; isolated configuration, unit suite and headless Pi lifecycle job declared | Linux CI headless workbench/restore passed with Xvfb and software Mesa; Cycles CPU and actual GUI undo and physical viewport capture still need separate qualification. |
| Windows x64 | Targeted | Public-repository `windows-2022` x64 runner; pinned official portable ZIP; isolated configuration, unit suite and headless Pi lifecycle job declared | Static/unit checks passed; the hosted VM's WGL Workbench path crashed. CI omits only GPU capture on Windows to test the remaining Blender lifecycle. Windows GPU capture, interactive undo and release qualification require separate capable validation. |
| macOS ARM64 | Deferred / unsupported | No required hosted integration job in the first release | Blender distributes an ARM64 DMG, but GitHub's standard hosted macOS ARM64 runner lists 7 GB RAM, below Blender's published 8 GB minimum. Require a suitable >=8 GB runner and real Blender testing before claiming support. |
| Windows ARM64 | Deferred / unsupported | None | Official archive exists; runner and full integration suite have not been validated. |
| Linux ARM64, macOS Intel | Unsupported | None | No matching 5.2 binary in the official release archive consulted for the baseline. |

Linux and Windows public GitHub-hosted runners meet the published Blender 8 GB minimum on paper; available runner memory and archive availability **do not prove** the Blender bridge is functional or that GPU/UI capture works there. Private-repository standard runners list only 8 GB for Linux/Windows; if validation runs in a private repository, use a larger runner or verify adequate capacity before treating the matrix as satisfied. Test actual Blender executable and extension loading on both supported platforms before release. Test viewport capture on an explicitly provisioned display/GPU runner or document and gate the feature per platform. Do not use `*-latest` runner labels for the baseline.

References (checked 2026-09-23): [official Blender 5.2 archive](https://download.blender.org/release/Blender5.2/), [Blender system requirements](https://www.blender.org/download/requirements/), [GitHub-hosted runner resources and labels](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). See task 11.1 for exact archive checksums and task 11.2 for implementing and verifying the jobs.
